Tokamak finds the GGUF models you already have, works out the best way to run each one on your GPU, launches them through llama.cpp, and turns the whole thing into a live instrument panel.

A tokamak is the machine that holds a fusion reaction inside a magnetic ring. Roughly the job here: contain a model that wants all of your VRAM, keep it stable, and get useful work out of it. The name also starts with “tok”, which is the only unit anyone here cares about.

WHY THIS EXISTS

Most local-LLM apps treat your hardware as a black box.

They will not tell you why a model runs at 4 tok/s instead of 190. They guess at GPU offload settings and never show the math. They cannot tell you which quantization you should have downloaded. Their idea of telemetry is a spinner.

No lock-in

Reads the caches you already have — Hugging Face, LM Studio, Ollama, any folder you add. Plain GGUF files, no proprietary blob store, no re-downloading. It even drives the llama.cpp binaries LM Studio already installed.

Measure, don’t guess

The estimator predicts what fits; the benchmark then actually runs the model and reports real numbers from your GPU. Recommendations are arithmetic you can inspect, verified by measurement.

Show everything

If the KV cache is about to overflow, you should see it coming. If half the layers spilled to CPU, the decode-rate cliff should be visible, not mysterious.

WHAT IT DOES

An instrument panel, not a chat box.

▤The model library

Scans the Hugging Face hub cache (HF_HOME respected), LM Studio’s folders, Ollama’s content-addressed blob store, and any folder you add.

Parses GGUF headers directly: architecture, quantization, native context, layer count, attention geometry. Split shards collapse into one entry; multimodal projectors show as a VISION badge on their parent.

⚖Hardware-aware auto-config

For each model it computes the best launch config for your GPU. KV cache cost comes from the real attention shape: layers × ctx × kv_heads × (k_len + v_len) × 2.

The context ladder shows every rung and how many layers fit at each, so you can trade speed for context deliberately instead of guessing.

◆The quant advisor

The answer to “which file should I download?”. Evaluates the whole GGUF ladder (F16 down to Q2_K, by effective bits-per-weight) against your VRAM including KV cache, and names the sweet spot.

F16 won’t fully fit — get Q4_K_M (4.2 GB headroom)

⚡Live telemetry

VRAM as fuel rods, one per GB, segmented into weights / KV in use / KV reserved. Hovering a model projects its footprint as ghost rods before you launch.

Flux trace scrolls the last 60 seconds of decode rate, GPU utilization and temperature. At 90% KV fill the third strip flips to a red pressure trace.

▶Chat and agent, kept apart

A CHAT tab for conversation and a CODE tab for agent work, each with its own transcript and session. The agent gets sandboxed workspace tools — reads run automatically, writes and shell commands stop at an approval card.

When a model stops early mid-task — which llama.cpp reports as an ordinary completion — the agent notices and pushes it to continue rather than quitting silently.

▣Sessions that keep everything

Every turn is persisted with full detail: content, reasoning, tokens, tok/s, sampler settings, model and launch config, timestamps, tool calls.

One plain JSON file per session — greppable, diffable, portable. No proprietary store, same philosophy as the model library.

GET STARTED

Build it from source.

There is no packaged release yet — Tokamak is v0.1 and built from source. Windows 10/11 with an NVIDIA GPU, since telemetry and benchmarking use NVML.

You’ll need

  • Rust (stable) and Node.js 20+
  • A llama-server binary — if LM Studio is installed, Tokamak finds its bundled builds automatically; otherwise put llama.cpp’s on your PATH
  • Some GGUF models on disk (LM Studio, Hugging Face, Ollama, or any folder)

Run it

git clone https://github.com/360NoScopeGuru/tokamak
cd tokamak
npm install
npm run tauri dev

# release build
npm run tauri build
